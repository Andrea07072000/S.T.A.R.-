1. What S.T.A.R. is

S.T.A.R. is an independent project that publishes engineering software together with the evidence of how it was checked. It has three lines: WORK, tools for everyday files and data that run in your browser; PROTECT, the Security Center; DISCOVER, research with its real status, including MURF and the interactive museum.

Every product and module carries one of seven states, defined once in the chapter on states. A state says how far an item has been checked; it is computed from the S.T.A.R. registry wherever a registry record exists.

2. Getting started: the Workspace, My Desk and the profile

Open the Workspace from the button at the top of every page. No account and no installation are needed. The first time a tool runs, the browser downloads its engine once; after that the tools answer locally.

At the top of the Workspace, My Desk lists twelve rooms. Without a profile every visitor sees them in the same order. The profile is a set of 36 multiple-choice questions in ten sections; its answers order the rooms and the suggestions and never hide anything. It is kept in your browser only if you save it, and can be exported, imported on another device and deleted.

If you allow it in the profile, My Desk also lists the five tools you opened last, on that device only.

3. First tasks, step by step

Five short tasks that use the site as it is today. The names in quotation marks are the labels of the buttons and fields.

Convert a value and keep a receipt

  1. Open the Workspace and choose “Convert units”.
  2. Select “Use an example” to fill in an example, or type a value and choose the two units.
  3. Select “Run”. The first run downloads the engine once; later runs are faster.
  4. Read the converted value and the exact factor used.
  5. Select “Download the receipt (JSON)” and keep the file with the result: it records the software, its version, the input and the checks.

Find out what can be checked in a table

  1. Open the Workspace and choose “What can I check in this file?”.
  2. Choose a file or paste a table; it is read in your browser.
  3. Select “Run”. The result says what each column seems to contain and which checks apply.
  4. Open a suggested check from the result: the whole-table check opens with your table, a single check opens with a value taken from it.

Check that a file is the one you were sent

  1. Open the Workspace and choose “Check that a file is unchanged”.
  2. Choose the file in “File”.
  3. If the sender gave you a fingerprint, paste it in “Expected value (optional)”.
  4. Select “Run” and compare: the result shows the fingerprints of the file and whether the expected value matches.

Run the Security Center on its built-in example

  1. Open the Security Center and select “Run on a built-in example”. The example is a synthetic project created in memory, with no real credentials.
  2. Read the summary: the number of findings by severity, the files read and what was not reported, and why.
  3. Read the table: findings are sorted from the most severe, each with what to do, the place and a short fingerprint, never the value.
  4. Select “Download the report (JSON)” to keep the report. Then select “Choose a folder” to check a folder of your own; it is read in your browser and never uploaded.

Create a profile and see your rooms

  1. Open the profile page from My Desk at the top of the Workspace.
  2. Answer the questions you want; every question can be skipped. The order of your rooms updates as you answer.
  3. Select “Save on this device” to keep the profile on this device, or “Export (JSON)” to keep it as a file.
  4. Back in the Workspace, My Desk shows the rooms suggested for you; every room is still listed.

5. The Workspace tools, one by one

Each tool below has the same sheet you find under 'About this tool' on its panel: what it solves, what it takes, how to read the result, the checks recorded in the receipt and what it cannot guarantee.

What can I check in this file?

Drop or paste a table: the page recognises tax codes, VAT numbers, IBANs, dates, coordinates and measurements, and selects the applicable checks.

Choose a CSV or text file, or paste a table. It is read here, in your browser; nothing is uploaded.

About this tool
What it solves
See at once which checks fit a table you have, instead of trying the tools one by one.
What it takes
A CSV or text file, or a pasted table. Example: a small register with tax codes, VAT numbers, IBANs, dates and amounts, with some mistakes.
How to read the result
What each column looks like, how many values are valid, and buttons that open the right tools already filled in.
Checks in the receipt
Each value is tested with the same engines as the released checks (tax code, VAT number, IBAN) and the same reader of tables as the column tool.
What it cannot guarantee
It recognises kinds from the form of the values, so it can be wrong on unusual columns; it examines up to 5,000 values per column.

Check a whole table in one pass

Numbers, tax codes, VAT numbers, IBANs and dates of a table, checked together: a cleaned copy, every value read differently, one receipt.

Choose a CSV or text file, or paste a table, and tick the checks to run. Each check takes the columns of its kind; nothing is uploaded.

About this tool
What it solves
Check a register, an export or a spreadsheet in one go, instead of value by value, and keep a cleaned copy with a single receipt.
What it takes
A CSV or text file, or a pasted table. Example: a small register with tax codes, VAT numbers, IBANs, due dates and amounts, with some mistakes.
How to read the result
A summary for each check, the list of values read differently (before and after), the cleaned table to download and one receipt for all the checks.
Checks in the receipt
Each code goes through the same engines as the released checks, row by row; the tests compare every row with python-stdnum and read the cleaned table back to prove your columns are unchanged.
What it cannot guarantee
It marks values, it does not correct them; valid means formally valid; columns are chosen from the form of their values.

Distance between two places

On the real shape of the Earth, with the direction to travel.

Type two places as latitude and longitude (decimal, like 41.9028, or degrees-minutes-seconds, like 41°54'10"N), or pick a city.

About this tool
What it solves
The real distance and starting direction between two places on the Earth, not a straight line on a flat map.
What it takes
Two places as latitude and longitude (decimal or degrees-minutes-seconds), or picked from the list. Example: Rome to New York.
How to read the result
The big number is the distance along the Earth's surface (WGS-84 ellipsoid); directions are from North, clockwise; the sphere line shows how far off a simpler formula would be.
Checks in the receipt
The distance is walked back along the computed direction to see where it lands (round trip), and compared with a sphere; both are in the receipt.
What it cannot guarantee
Not a road, sea or flight route; no heights; not for navigation or safety decisions; only as accurate as the coordinates you type.

Decimal degrees, degrees-minutes-seconds and UTM, with a round-trip check.

Type a latitude and a longitude in any common format.

About this tool
What it solves
Rewrite a position in the formats maps and GPS devices use, without copying mistakes.
What it takes
Latitude and longitude in decimal degrees or degrees-minutes-seconds, with N/S/E/W. Example: Milan cathedral.
How to read the result
Decimal degrees, degrees-minutes-seconds, and UTM (zone, easting and northing in metres).
Checks in the receipt
Each conversion is converted back and compared with your input; special and polar UTM zones are flagged.
What it cannot guarantee
No change of datum (everything is WGS-84); UTM is not defined near the poles.

Check a column of numbers

Find missing, mistyped and suspicious values in a CSV; summary statistics.

Choose a CSV file, or paste the text. From Excel, LibreOffice or Google Sheets: select the column with its title, copy, and paste it here (or save the sheet as CSV; .xlsx files cannot be opened directly). Separators , ; | and tab are recognised; Italian numbers like 1.234,5 are read correctly and every conversion is listed.

About this tool
What it solves
Find what is wrong in a column of numbers before you trust a total or an average.
What it takes
A CSV file or pasted text; separators , ; | or tab; Italian numbers such as 1.234,5; text saved by Excel on Windows. Example: daily readings with mistakes.
How to read the result
How many values, the mean and median, the spread, and the values to double-check; every converted, missing or unreadable cell is listed; you can download a checked copy.
Checks in the receipt
Mean and median are computed by released S.T.A.R. packages; suspicious values are flagged by a stated rule (modified z-score above 3.5).
What it cannot guarantee
It cannot determine whether a suspicious value is actually wrong; it identifies the values to review. It does not open .xlsx files.

Fit a straight line

The trend in your readings, and how sure it is (slope and intercept with their uncertainty).

Choose a CSV file with two columns of numbers, or paste them. The first column is x and the second y, unless you choose otherwise after the first run.

About this tool
What it solves
See whether one quantity grows with another, and by how much.
What it takes
Two columns of numbers (x and y) as a CSV file or pasted text. Example: energy used against hours of work.
How to read the result
The line y = slope × x + intercept, the uncertainty of each, R² and the typical distance of the points from the line; a plot.
Checks in the receipt
The fit is computed by a released S.T.A.R. package; the uncertainties come from how the points scatter.
What it cannot guarantee
A straight line only. It does not prove cause and effect, and its uncertainty assumes independent, evenly scattered points.

Check that a file is unchanged

A fingerprint of the file (SHA-256 and others), compared with the value you expect.

Choose a file (up to 100 MB). Optionally paste the value it should have, as published by whoever sent it.

About this tool
What it solves
Show that a file is exactly the expected one — after a download, a copy, or before you send it.
What it takes
Any file, read only by your browser; optionally the value you expect (SHA-256, SHA-1, MD5 or CRC-32). Example: a short text file.
How to read the result
The fingerprints of the file; if you paste an expected value, a clear match or no match.
Checks in the receipt
SHA-256, SHA-1 and MD5 by Python's hashlib; CRC-32 by zlib and, for files up to 1 MB, also by the released star-crc, bit for bit.
What it cannot guarantee
A match proves the file is identical to the one the value was computed from — not that the file is safe, nor that the value came from someone you trust.

Type a value and choose the units.

About this tool
What it solves
Convert a value between units without slips of a power of ten.
What it takes
A number and two units of the same kind. Example: 26.2 miles in kilometres.
How to read the result
The converted value and the exact factor used.
Checks in the receipt
Factors from exact SI definitions in a released S.T.A.R. package; units of different kinds are refused.

Check an Italian tax code

Codice fiscale: check character, omocodia, sex, date and place of birth.

Type the 16 characters (spaces and lower case are fine). Optionally add surname and name to check their letters.

About this tool
What it solves
Catch a mistyped tax code before it goes on an invoice, a contract or a form, and read what the code says.
What it takes
The 16 characters; optionally surname and name. Example: RSSMRA80A01H501U, the textbook example.
How to read the result
Valid or not; the sex and possible dates of birth coded in it; whether it is an omocode, with its original form.
Checks in the receipt
The check character recomputed (D.M. 23/12/1976 tables); omocodia letters in the official order; a real birth date; surname and name letters if given.
What it cannot guarantee
It cannot say the code was issued or belongs to a living person; the place of birth is shown as a code, not a name.

Type the 11 digits; an IT prefix and spaces are removed and listed in the receipt.

About this tool
What it solves
Catch a mistyped VAT number before you issue or pay an invoice.
What it takes
11 digits, with or without IT. Example: a made-up number that only satisfies the rule (serial 0000001, office 001).
How to read the result
Valid or not; the serial and the office code; the check digit expected.

The check digit with the Italian rule — which gives the same digit as the Luhn rule on 11 digits, and the receipt says so; the office code in its allowed ranges; a serial that is not zero.

Catch a mistyped IBAN before a payment, and see how an Italian IBAN is made.
What it takes
An IBAN of any country that uses one. Example: IT60 X054 2811 1010 0000 0123 456, the example used in banking documents.

Count the working days between two dates, or find the date N working days after a start. Dates as 2026-12-31 or 31/12/2026.

About this tool
What it solves
Count working days or set a deadline without forgetting Easter Monday or 4 October.
What it takes
Two dates, or a date and a number of working days; your patron saint's day if it is a holiday where you work. Example: December 2026.
How to read the result

Compare two tables

Two versions of a list: rows removed, rows added, and every cell that changed, matched by a key column.

Paste the old table in A and the new one in B, with a first row of column names (CSV, semicolons or tabs). The key is the column that identifies a row, such as a code; leave it empty to use the first column the two tables share.

About this tool
What it solves
See exactly what changed between two versions of a price list, an inventory or a register, without checking row by row.
What it takes
Two tables with column names and a key column. Example: a parts list before and after an update.
How to read the result
Rows removed and added; for each changed row, the column and the old and new value.
Checks in the receipt
Rows matched by key, duplicate keys refused; counts compared with pandas (merge and compare) on the same tables.
What it cannot guarantee
It matches rows only by the key; 0.10 and 0.1 are the same number, but 10 % and 0.1 are different values.

Paste a table with a first row of column names. Choose how similar two rows must be to be reported (1 = identical apart from spaces, capitals, accents and punctuation, 0.9 = about one character in ten may differ), and optionally which columns to compare, separated by commas.

About this tool
What it solves
Clean a contact list or a register before you send, count or import it.
What it takes
A table with column names; how similar rows must be; the columns to compare. Example: five contacts, two of them written twice.
How to read the result
Groups of identical rows by line number, and pairs of nearly identical rows with their similarity.
Checks in the receipt
Spaces, capitals, accents and punctuation normalised before comparing; edit distance checked against rapidfuzz.
What it cannot guarantee
Similar is not the same person: two rows that look alike can be two people, and the same person written very differently is missed.

6. Receipts

A receipt records which software produced a result and from what. Keep it with the result or attach it to a report; anyone can recompute the fingerprint of the input and compare.

1. which S.T.A.R. software performed the work, with its version; 2. the input provided, with its SHA-256 fingerprint (the same input always yields the same fingerprint); 3. every change applied to the input before use; 4. the checks performed, each passed or failed; 5. the limits, and any item requiring human review. Keep it with the result, or attach it to a report.

The seven states and what each requires:

What the check does not cover

  • known vulnerabilities in dependencies (no vulnerability database is used offline)
  • the Git history: secrets removed from the files but still in earlier commits
  • binary files, archives inside the folder, and files larger than the size limit
  • secrets in formats without a rule, however random: a value is reported only if a rule recognises its format or it is assigned to a secret-looking name
  • whether a secret that was found is still valid (it is never sent anywhere to be tested)
  • secret-looking assignments whose value has no digit or is only letters (the generic rule requires letters and digits, to avoid reporting words and identifiers)

9. MURF

Digital twins that combine reference solvers, fast surrogate models and independent checks, and that say how far each answer can be trusted. In development: this page says exactly what exists today.

A full simulation is accurate and slow; a fast model is quick and right only inside the region where it was checked. A multi-fidelity twin keeps both: it answers fast where the fast model is known to hold, calls the reference solver where it is not, and shows which of the two produced each number.

ComponentWhat it isWhat it is notState
MURF Museumthe 3D museum of this site: forty rooms of declared models that show the ideasa validated simulatorPrototype, for teaching
MURF Assistantan agent for a small set of tasks, with budget, time limit, log and human approvalan agent with unlimited permissionsPlanned
MURF Twin Enginetwins specialised by domain: reference solver, surrogate, uncertainty, escalation, independent checksone model of everything; a space twin is not a chip twinResearch
MURF Connectadapters to the libraries, solvers and data an organisation already usesa replacement for its data centrePlanned

The first twin starts from an engine already measured, which is not yet a public package. S.T.A.R.'s two-dimensional collision probability agrees within 1e-7 (relative) with the adjusted value of NASA CARA on 53 of 53 real conjunctions and with Orekit on 48 of 48. Against a different CARA value, computed with another encounter definition, an earlier pre-registered rule of 1e-6 was not met on 11 of 48 cases; the Research page reports it. On 29 of those 53 cases the assumptions of the two-dimensional method do not hold. The question of Twin 0 is whether a second, more faithful level can be called only where the first one stops being valid, with a rule measured in advance.

It does not replace CPUs, GPUs, CUDA, PyTorch or cloud computing: it uses them where they are strong. No speed-up or accuracy figure is published before a benchmark on declared hardware with its baseline. A fast answer is not proof of accuracy, and a model's own uncertainty is not a guaranteed error bound.

13. Frequently asked questions

Do I need an account or an installation?

No. The Workspace and the Security Center run in the browser. The packages are installed with pip only if you want them in your own software.

Are my files uploaded?

No. The Workspace tools and the Security Center read the files you choose inside your browser. The Security Center opens no connection while it scans.

Why is the first run slower?

The first time a Workspace tool runs, the browser downloads its engine once (about 12 MB). Later runs use the copy already loaded.

Does an AI model look at my data?

No. The Workspace tools and the Security Center are deterministic programs: the same input always gives the same output, and no language model is involved.

What does 'Released & Verified' mean?

Every gate of the S.T.A.R. registry passed, including a mutation score of at least 0.85 and at least two independent implementations that agree within a stated tolerance. It is not a certification.

Does S.T.A.R. software have a certification or a flight qualification?

No. It is tested and compared with independent references; it has no certification and no qualification for aircraft or spacecraft.

A folder with no findings: is it safe?

No. It is a folder in which these rules found nothing. Every report lists what the check does not cover.

Does the Security Center show or send the secrets it finds?

Neither. A finding shows the rule, the file, the line, the column, the length and the first 12 hexadecimal digits of the SHA-256 of the value, never the value itself.

What should I do when the check finds a secret?

Treat it as exposed: revoke or rotate it with its provider, then remove it from the files and from the version history. Removing it from the files alone is not enough.

Can I use the check in a CI job?

The command-line version exits with 1 when a finding reaches the chosen severity, which stops a pipeline. It will be published with its first release; until then it is part of the engineering repository.

Why does the check not report a value I know is a password?

To avoid reporting words and identifiers, a value assigned to a secret-looking name is reported only if it has letters and digits and enough randomness. Values made only of letters are in the list of what is not checked.

What is a receipt?

A record of a result: the software and its version, the input with its SHA-256 fingerprint, every change applied to the input, the checks performed and the limits. It lets anyone check that the result came from that input.

How do I verify a download?

Each file on the downloads page has its SHA-256 fingerprint; compute it on your copy and compare. A small script on the site does it for all files.

What is the profile for, and where is it kept?

It orders the rooms of the Workspace and the suggestions. It is kept in your browser only if you save it, never sent anywhere, and can be exported, imported and deleted.

How do I delete everything the site kept on my device?

Use 'Delete the profile' on the profile page, which also removes the list of recent tools, or clear the site's data in your browser settings.

Why does a room say 'No page yet'?

Because it is specified and not built. Its state is Planned, and the manual and the site say so instead of showing a mock-up.

What is MURF?

A research line on multi-fidelity digital twins with independent checks. Its first twin, on the collision probability of two satellites, is being measured against NASA's published values with a rule written before the measurement.

Is the museum a simulator?

No. Each exhibit runs a declared model to explain an idea. Results of the S.T.A.R. software are on the evidence pages, not in the museum.

What is the failure observatory?

The public list of defects found in S.T.A.R. software, including those found before release, with what was changed and the test that now guards against them.

Why do two pages sometimes show different numbers?

They should not. Counts of tools, products and packages are read from the registers when the site is built, and the build stops if a page quotes a different count; other figures come from evidence files. If you find a difference, please report it.

How do I report a vulnerability?

Write to the contact address with the details, and please do not publish it before an answer. The Security Center page describes the process.

Can I use the packages in commercial software?

The packages are published under the Apache License 2.0; its terms apply. Each package page lists its licence and its dependencies.

Which Python versions do the packages support?

Each package page states the supported versions and the dependencies, as declared in the package itself.

Which browsers are supported?

The automated checks of this site run in Chromium. Other recent browsers are expected to work but are not covered by those checks.

What does a label like SIMULATED or CROSSCHECKED on a number mean?

Where the number came from: a model, a surrogate, a comparison with an independent implementation, a formal proof or a real measurement. A number carries only the labels its evidence supports.

Who is behind S.T.A.R.?

An independent project by Andrea Cavazzini, Italy, not a company. The About page has the details.

Can S.T.A.R. work on my organisation's data?

Yes, as tailor-made work or an independent assessment, described on the pages for organisations.

Why are some tools marked as a preview?

A product is marked until its live test is recorded. The mark disappears when the test passes.

What happens to the Workspace when I close the tab?

What you entered or uploaded is erased with the tab. Only a saved profile and, if allowed, the list of recent tools stay on the device.

In which languages is the site available?

English and Italian. The texts of both languages are generated from the same sources.

14. Glossary

Conjunction
a close approach between two objects in orbit.
CDM
Conjunction Data Message, the CCSDS standard file describing a conjunction.
Collision probability (Pc)
the probability that two objects come closer than their combined hard-body radius.
Entropy (of a value)
a measure of how random a string of characters is; low values are typical of words and placeholders.
Fingerprint
the SHA-256 digest of a file or value; equal inputs always give equal fingerprints.
Held-out set
data never used while writing a method, kept apart to measure it honestly.
Independent implementation
a second program, written separately, that computes the same quantity and is compared with the first.
Monte Carlo
a method that estimates a quantity by repeating random trials and counting outcomes.
Mutation score
the share of deliberately introduced errors that a test suite detects.
Security check
a check run before an action, here before sharing a folder or handing it to an AI agent.
Preregistration
writing the method and the acceptance rule of a measurement before running it.
Receipt
the record of a result: software, version, input fingerprint, changes, checks and limits.
Registry
the S.T.A.R. records of capabilities, benchmarks, evidence and failures, from which states and counts are computed.
Surrogate model
a fast approximate model trained or fitted to reproduce a slower reference.
Tolerance
the largest difference accepted between two results for them to be said to agree.
Twin (digital twin)
a model of a specific system, kept consistent with references and with its stated domain of validity.
