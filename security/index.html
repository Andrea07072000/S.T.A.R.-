Security Center Beta

Checks that find known risks before you share, publish or hand a project to an AI agent. Each report says what was checked, what was found, and what was not checked.

First module available; the others are planned and listed below with their state.

How your files are handled: the folder you choose is read by your browser, file by file, and never uploaded. The page opens no connection while it scans. The report shows where a secret is and a short fingerprint of it, never the secret itself.

Folder security check

Secrets (API keys, tokens, private keys, passwords in addresses, secret-looking assignments), files that should not be in a repository, and risky configuration of CI workflows, containers and installs.

How it was tested

  • Labelled corpus, written together with the rules (190 files, 5 generations): precision 1.000, recall 1.000. It shows that the rules do what they are written to do; it is not a measure of real-world performance.
  • Same corpus, lines holding a secret: this check finds 170/170 of them, the five patterns used until now in our Endurance agent find 45/170.
  • Folders never used to write the rules: 55,471 files of external open-source repositories gave 151 findings before the corrections; false alarms: 38 (precision 0.75). The corrections are listed in the failure observatory, under star_preflight, and that set is no longer independent.
  • A second set never seen, 3,915 files of another project of ours: 219 findings with rules 0.1.1; false alarms: 1. That false alarm was then corrected, so this set is no longer independent either. These two sets count false alarms only: how many secrets the rules miss on real repositories is not measured here.
  • Two engines, one in Python and one in the browser, read the same rules and must agree: 22 comparisons on the corpus and on real folders, all identical.
  • Mutation testing of the Python engine: 69 of 69 deliberate faults caught by the tests (score 1.000).

From the command line

The same rules as a Python package with no dependencies, for a pre-commit hook or a CI job. It exits with 1 when a finding reaches the chosen severity. It will be published with its first release; until then it is part of the engineering repository.

python -m star_preflight my-project --fail-on high
